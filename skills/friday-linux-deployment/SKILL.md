# Friday Linux 部署与实机验收

先确认任务是新装、替换主机，还是临时借用一台电脑验收。临时验收只接管要测的设备；记录原服务的摄像头所有者、云台模式和语音暂停状态，安排好交还时机。普通安装到控制面就绪即可，无须默认开启家电联动。

## 选对主机、存储与镜像

- 在目标主机运行 `uname -m`、`docker info --format '{{.OSType}}/{{.Architecture}}'`、`docker context show`。记录 CPU、内存、Docker 存储位置和镜像摘要；Mac 上模拟 amd64 与原生 Linux 的测量分开报告。
- Ubuntu Live 适合在保留原系统时做临时测试。用 `lsblk -o NAME,TRAN,SIZE,FSTYPE,LABEL,MOUNTPOINTS,RO`、`findmnt`、`df -h` 区分内存覆盖层、U 盘和内置盘。如果 Docker 数据或缓存放在 U 盘，启动引擎前确认实际挂载、剩余空间，在专用目录做一次小文件写入、同步和读回。设备重新枚举后按设备身份核对挂载。
- Live 桌面重启可能丢失 SSH 服务、主机密钥和 Docker 安装，即使缓存卷还在。重新连接时，将新 SSH 指纹与目标机本地显示的指纹核对。遇到包管理器锁，等待当前安装进程结束再重试；看到 `SQUASHFS error`、USB 断开或文件系统转为只读，则暂停写入并核对内核日志、USB 口及介质。网页能打开仅能验证网络路径。
- 在项目索引的 Compose 目录按已发布的不可变镜像摘要拉取，给试验分配独立项目名和卷。先检查模拟控制面及 `camera-sdk-status`，再准备任务所需的模型。摄像头 SDK 由首次启动按锁文件下载和校验，重启可复用已验证缓存；保留随附许可证与非商业说明。固定模型文件和版本，重新使用匹配 Linux 架构的运行环境。

## 切换到真实设备

核对容器可达的 Home Assistant（HA）地址、实例身份、设备注册表和原有授权范围。短期测试可通过 SSH 回环转发复用现有 HA；正式迁移依项目文档备份并导入私有卷。临时会话授权只放受限内存目录，真实音视频和授权文件留在测试现场。

先分层查摄像头：属性回读 → SDK 局域网握手 → 新鲜解码帧或音频包 → CPU 推理 → 设备动作。优先试原生 Linux 直连；排查握手时区分宿主和容器的 UDP 返回路径。需要短时用 host 网络定位时先核对监听地址，避免扩大管理页面的暴露范围。确认原采集进程释放租约后，再让测试机打开同一摄像头。

## 需要实物效果时怎样测

| 能力 | 操作和通过依据 |
| --- | --- |
| 人体云台 | 等真实画面就绪、人在中央并锁定，再给走动提示。说清“你面朝镜头，以自己的左右手为准”，按场地安排去程、折返和停留。对齐帧数、锁定变化、步进方向和提示时间；由本人确认折返跟上及停稳后是否多转，单有指令回执无法判断镜头运动。 |
| 摄像头语音 | 明确使用摄像头 SDK 麦克风，只在有界测试窗口收音，提示“正在收音”后让人说预定短句。核对输入来源、连续片段时长、丢包和 CPU 识别时间。发生断点时保留来源、时效检查，把连续片段分别识别，分别记录是否有一个片段命中整句与使用者确认。测试短句不进入家电命令路由。 |
| 家庭屏播报 | 先核对同一台设备的通知实体、可用动作、原音量及静音。在用户准备试听时发送一条“播放文本”消息，记录 HA 接受情况和本人是否听清。Xiaomi Mini 在这条路径上自行合成；报告合成位置，勿据此推断完全离线或支持本地音频播放。 |
| KTV 分离 | 使用许可明确的带人声片段，核验输入与模型摘要，通过产品的 CPU 分离入口生成两轨。要测本轮推理，使用独立可写缓存并核对缓存未命中。记录输入时长、计算耗时、采样率，对照原曲试听伴奏的人声残留和失真。 |

## 收尾与记录

先让采集结束、确认测试机释放租约，再按原策略交还摄像头；若用户期间另作调整，保留其新设置。回读图像新鲜度、云台模式、音量和静音，移除本轮临时容器、会话和转发。使用 Live U 盘时先把脱敏结果保存到可保留的位置，正常关机后按卸载提示或在关机完成时拔盘。
