# 维护项目索引

本页说明怎样维护元仓库。实际服务的部署、停止、重启、升级和故障排查见[部署维护总览](operations.md)。

## 新增或调整仓库

1. 在 `repos.json` 填写稳定标识、名称、官方链接、职责、类型与使用关系。
2. 在 `repos/` 增加对应简介，说明部署位置和与其他仓库的关系。
3. 更新 README 索引表；依赖关系变化时同步架构图。
4. 运行 `python3 scripts/check_index.py`，检查本地链接与登记一致性。

## 产品更新后

先核对用户入口、按钮名称、控制范围与实际可用条件，再更新用户手册。截图应来自可重复的示例服务，并标明模拟、未配置或已验证的范围。真实家庭画面、账号授权文件和本机备份保留在各自私有环境。

手册发布前执行链接和构建检查，推送文档仓库 main 后确认 Pages 发布结果。本索引不安排自动拉取、部署或设备动作。

## 部署或维护工具更新后

1. 安装器修改提交到 Friday 主仓，同步 `friday-user-guide/docs/assets/scripts/` 的下载副本和对应 SHA256 清单；启停工具继续在文档仓库维护，保留许可证。
2. 同步用户手册的安装、启停、升级和常见问题，确认公开源码链接与 Pages 下载内容一致。
3. 在本仓库的[部署维护总览](operations.md)同步版本、依赖升级原因、操作入口和验证范围，并在 README 保留易发现的入口。
4. 相关职责变化时更新 `repos.json`、对应 `repos/` 简介和架构说明；分别记录本机修改、已推送提交与上游发布状态，补上可公开访问的提交和分支链接。
5. 提交前运行 `python3 scripts/check_index.py`，核对公开链接，不纳入私有配置、凭据、家庭截图、备份或原始日志。

## 变更说明要包含什么

说明哪个仓库变了、用户行为怎样变化、依赖关系是否改变，以及文档验证范围。源码版本、服务健康与物理验收结果分别说明，不用一次软件回归代替现场确认。
